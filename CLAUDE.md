# Djaber v2 — instructions for the coding model

## What this is
Multi-tenant SaaS: AI sales agent for Facebook Messenger / Instagram shops in Algeria. Monorepo (pnpm + Turborepo): `apps/api` (NestJS 11 HTTP + WS), `apps/worker` (NestJS BullMQ processors + schedulers), `apps/web` (Next.js App Router), `packages/db` (Prisma, Postgres 16), `packages/shared` (zod schemas, validators, enums, error codes, i18n keys), `packages/ui` (design system). Redis 7 + BullMQ, S3-compatible storage, Vercel AI SDK, Chargily Pay (CIB/Edahabia rails) behind `PaymentGateway`, Google Play / App Store IAP, ZR Express / EcoTrack / Yalidine couriers, Google Sheets, FCM, Resend.

**Never ask the owner a question; apply `08-coder-playbook.md` §6 "If something seems missing" and record the assumption in `docs/implementation/assumptions-log.md`.** Every decision is closed (`docs/specs/README.md` Decisions, `docs/audit/decisions-log-2026-10-11.md`).

## Prerequisites (check once before M0; install what is missing, then continue)
- Node 22, pnpm (present), Git (present). **No Docker on this machine — local development and tests run without Docker** (owner decision 2026-10-11; verified working on this PC). This paragraph overrides every mention of `docker compose`, Testcontainers, MinIO and Mailpit for local development in the other documents (Docker images stay only as the staging/production packaging of M0's CI section; write the Dockerfiles but do not run them locally):
  - **Postgres 16**: npm package `embedded-postgres@16.14.0-beta.17` (bundles Postgres 16.14 with `pg_trgm`, `pgcrypto`, `unaccent`, `uuid-ossp`). `pnpm infra:up` runs `tools/infra/start.mjs`: data dir `.local/pg`, port `54329`, user/password/database `djaber`, `persistent: true`; then `CREATE EXTENSION IF NOT EXISTS pg_trgm, pgcrypto, unaccent`. `DATABASE_URL=postgresql://djaber:djaber@localhost:54329/djaber`.
  - **Redis**: `tools/infra/redis.mjs` — on Windows it downloads once the native Redis 7.2 build of github.com/redis-windows/redis-windows into `.local/redis-bin` (the Windows binary of `redis-memory-server` is Redis 3.0, which BullMQ rejects); on Linux/macOS `redis-memory-server` builds Redis 7.2. Port `63799`. `REDIS_URL=redis://127.0.0.1:63799`. Queue state is not persisted between restarts in dev; that is accepted.
  - **Object storage**: `StorageService` has two drivers behind one interface: `local` (files under `.local/storage`, served by the API at `/dev-storage/*`, used when `STORAGE_DRIVER=local`, the dev and test default) and `s3` (staging/production). Same keys and signed-URL semantics in both.
  - **Mail**: `MailService` drivers `file` (writes `.eml` + a JSON line to `.local/mail/`, dev and test default; tests read that folder) and `resend` (staging/production).
  - **Integration tests**: instead of Testcontainers, `apps/api/test/setup/global-setup.ts` starts one embedded Postgres on a free port with a temp data dir (`persistent: false`), runs `prisma migrate deploy`, starts one `RedisMemoryServer`, and tears both down in global teardown; each test file uses its own schema or truncates tables.
  - `.local/` is git-ignored. `pnpm infra:down` stops both servers.

## Non-negotiable rules
1. **Tenancy**: every business table has `workspaceId`; every query is scoped by `TenantContext`; cross-workspace access returns 404. Never read `workspaceId` from the request body.
2. **Permissions**: every route has `@RequirePermission` (merchant) or `@RequirePlatformRole` (admin) or is explicitly `@Public()`. Keys only from `permission-matrix.ts`.
3. **Idempotency**: `Idempotency-Key` required on the routes listed in `docs/implementation/api-contract.md` §1.7; every BullMQ job has a deterministic `jobId` and is safe to run twice; AI tool calls are persisted before execution and replayed on retry.
4. **Side effects through the outbox** inside the transaction: WS events, notifications, Meta sends, webhooks, Sheets. Never call Meta, couriers, Chargily, Google or AI providers from an HTTP handler (exceptions listed in `03-events-and-jobs.md` §7).
5. **Business rules live in services** (`04-business-rules.md`), never in controllers or UI. Stock/cash/aggregates change only through `OrderEffects` / `SaleEffects` / `PurchaseEffects`. Aggregates are recomputed, never incremented.
6. **No invented features, no questions**: if a field, status, copy string, screen, endpoint or rule is in neither the specs, the Figma, nor `docs/implementation`, apply the matching row of `08-coder-playbook.md` §6 "If something seems missing" and append one line to `docs/implementation/assumptions-log.md`. Never stop a task to ask.
7. **Per screen**: all states from `12-screen-states.md` + the GLOBAL catalogue (skeleton, empty, filtered-empty, error, offline, 403, 404, conflict, leave guard), filters in the URL, one `Actions ⌄` dropdown per row with disabled reasons, every string an i18n key (fr/ar/en, `pnpm i18n:check` green), RTL-safe (logical CSS, `<Ltr>` for numbers/phones/SKUs), Storybook story per state, Playwright test per AT id.
8. **Errors**: only codes from `11-error-catalogue.md` (aliases of 11 §13 never appear in code except in `packages/shared/src/errors/aliases.ts`); envelope `{ error:{ code, message, params?, fields?, details?, ref } }`; success envelope `{ data, meta? }`; shown inline inside dialogs; form content preserved.
9. **Security**: argon2id, EdDSA JWT 15 min + rotating refresh, AES-256-GCM for tokens/credentials, raw-body signature check on every inbound webhook, strict CORS allowlist, PII masked in logs and admin viewers, audit for every sensitive action. **Secrets from V1 (owner authorisation 2026-10-11):** you may read the V1 environment files in `E:\Dev App\djaber` (`.env*`) to obtain the values the new app needs (Meta app id/secret/verify token, Chargily keys, AI provider keys, courier credentials, Google OAuth client, mail/SMS/FCM keys). Rules: (a) copy values only into this repo's git-ignored `.env` / `.env.local` files, mapped to the variable names of `.env.example`; (b) never print, quote, log, commit, or write a secret value into any tracked file, test, fixture, commit message, log file or chat output — refer to variables by name only; (c) confirm `.env*` (except `.env.example`) is in `.gitignore` before writing; (d) `.deploy-secrets*`, `.github-deploy-key*`, SSH keys and server passwords stay off-limits — never open them; (e) never use V1 database credentials to write: the V1 database is read-only for this project and only the migration rehearsal of `07-non-functional.md` may read it; (f) production safety: prefer test/sandbox keys when V1 has both (Chargily test mode, courier sandbox); do not register or change the Meta webhook URL, app settings, or page subscriptions from development (the live V1 app keeps receiving its webhooks); do not send real messages to customers, create real payments, or create real shipments from dev or tests — automated tests always use the fake adapters; (g) if a value is absent from V1, leave the variable empty and keep the fake adapter for that service. V1 code may be read for behaviour.
10. **Tests are part of the task**: unit for rules, integration for every endpoint (happy, 422, 403 per role, cross-workspace 404, idempotency, 409), acceptance tests named by their AT id from `13-acceptance-tests.md`. No `it.skip`, no `--no-verify`.
11. **Time & money**: `Africa/Algiers` for periods, UTC stored, integer DZD, Latin digits, `12 500 DA`.
12. **Commits**: conventional commits citing spec IDs and Figma frame names; small PRs; checklist from `08-coder-playbook.md` §3 in the description; attribution footer as configured.
