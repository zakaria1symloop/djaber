## Top findings
1. Valuation reports and product analytics count untracked (digital/service) products as 1,000,000 units (`UNTRACKED_QUANTITY`, user-stock.controller.ts:38) — not filtered in reports.controller.ts:1096-1131,1216-1219,1301-1304,1416-1443 and user-analytics.controller.ts:27-37.
2. Profit & Loss subtracts COGS **and** caisse purchase expense rows → purchases counted twice (reports.controller.ts:125-217).
3. `sendOrderToDelivery` ignores `order.wilayaId/communeName/isStopdesk`; destination = `toWilayaId || provider.senderWilayaId || 16` (user-delivery.controller.ts:349).
4. Cross-sell "conversions" = every ordered pair in an AI order with an active rule, no link to impressions (ai.service.ts:936-953).
5. Legacy page-scoped `/api/stock` + `src/lib/stock-api.ts` are dead code, still mounted.
6. Revenue defined 3 ways: reports/sales stats = delivered orders only; order stats/analytics = all except cancelled/returned (pending included); payments report = amountPaid of non-cancelled/returned.

## Products (`user-stock.controller.ts`)
- Limits: NAME/SKU 255, DESCRIPTION 5000, COLOR 20, UNIT_LABEL 50, URL 2048, PHONE 50, ADDRESS 1000, NOTES 5000, REASON 255, MOVEMENT_NOTES 2000, EXPENSE_DESCRIPTION 1000. Movement types `in|out|adjustment|return`. Expense categories `marketing, shipping, packaging, customs, storage, other`.
- No "service" entity: `Product.trackStock=false` = digital/service; quantity forced 1,000,000, minQuantity 0; no opening movement; `adjustStock` rejects (`PRODUCT_NOT_STOCK_TRACKED`); cannot have variants.
- Dashboard payload: `stats{totalProducts, lowStockProducts, totalCategories, totalSuppliers, totalStockValue, totalRetailValue, totalItems}` + `recentMovements`(10). lowStock = `isActive && trackStock && quantity<=minQuantity` (product level only). Stock value = plain products (hasVariants=0, trackStock=1) + active variants.
- Create: sku, name required (≤255); costPrice>0, sellingPrice>0 required; selling ≥ cost else `PRODUCT_SELLING_BELOW_COST`; optional description, categoryId (own), unitId (system/own), unit label (default 'piece'), imageUrl, hasVariants (validated but **not written**), trackStock (default true). Quantity: positive integer required (unless hasVariants → ≥0 default 0, untracked → forced). minQuantity ≥0 default 0. SKU unique among live products; archived SKU freed in-transaction; P2002 → `PRODUCT_SKU_ALREADY_EXISTS`. Opening `in` movement reason 'Initial stock' when tracked & qty>0.
- Update: sku, name, description, categoryId, unitId, unit, imageUrl, isActive, costPrice/sellingPrice (min 0), minQuantity, trackStock. **No selling≥cost check on update. Quantity not accepted.** trackStock toggle: ON→OFF sets qty 1,000,000; OFF→ON resets qty 0; no movement logged.
- Delete: soft (`isActive=false`), SKU rewritten `<sku>#deleted-<ts>`, original in `archivedSku`; local image files unlinked, ProductImage rows kept; GCS objects not deleted.
- adjustStock: type in|out|adjustment|return; quantity ≥0 (0 only for adjustment, `STOCK_QUANTITY_ZERO`); reason ≤255 and notes ≤2000 free text (no fixed list); rejected for variant products (`PRODUCT_HAS_VARIANTS`) and untracked. `out` conditional decrement → `STOCK_INSUFFICIENT`; `adjustment` sets absolute qty (SELECT … FOR UPDATE).
- Movements list: filters productId, type, startDate, endDate (end-of-day applied; reversed → `INVALID_DATE_RANGE`); pagination default 50 max 200; returns `{movements,total}` with product {id,name,sku}.
- Categories: name ≤255 required, description ≤5000, color ≤20 default `#6B7280`; dup → `CATEGORY_ALREADY_EXISTS`; list filters search, hasDescription, color list, min/maxProducts (in-memory); delete blocked `CATEGORY_IN_USE{count}` when active products use it (inactive → SetNull).
- Product list: lowStock filter in SQL; margin filters (min/maxProfit, min/maxMargin) load all + paginate in memory. Margin: `expPerUnit = fixed/max(qty,1) + perUnit; trueCost = cost + expPerUnit; margin% = (selling−trueCost)/selling×100`.
- Analyze image: multer field `image`; sends base64 + user's category/unit names; best vision model temp 0.3, 1000 tokens; returns `{name, description, suggestedCategory, suggestedUnit}`; errors `IMAGE_ANALYSIS_UNAVAILABLE`(503) / `IMAGE_ANALYSIS_FAILED`.
- Suppliers: name required, email, phone, address, notes, isActive; soft delete; `totalSpent` includes cancelled purchases.

## Sales (`user-sales.controller.ts`)
- Number `SL-YYYYMMDD-NNNN` (UTC), in-transaction, 3 retries. Payment methods `cash, card, transfer, ccp, other`; statuses `pending, partial, paid`.
- Create: customerName ≤191, customerPhone ≤50 (**not validated, not linked to Client**), notes; items {productId, variantId, quantity>0, unitPrice≥0|null, discount≥0}; discount, tax, paymentMethod (cash), paymentStatus (default **paid**), amountPaid; saleDate ≤ +1 day. Products must be active & own. Variant products need active variantId (`SALE_VARIANT_REQUIRED/NOT_FOUND`). Line = unitPrice×qty − lineDiscount; total = subtotal − discount + tax. amountPaid clamped [0,total]; absent → paid status ⇒ total else 0; derived 0→pending (paid if total≤0), ≥total→paid, else partial. Stock conditional decrement → `SALE_INSUFFICIENT_STOCK`; `out` movement reference sale.id; **SaleItem has no variantId** (productName "Product - Variant").
- Caisse: paid>0 → one auto income row category sale, reference saleNumber, sourceId sale.id, dated now.
- updateSalePayment: paymentStatus, paymentMethod, amountPaid, notes; pending→0, paid→total, partial w/o amount keeps; paid change → delete auto rows + create one.
- deleteSale: blocked when amountPaid>0 (`SALE_DELETE_PAID`); restores stock from `out` movements (fallback items); writes `return` movements; deletes auto caisse rows; hard delete.
- Stats: periods today/week/month/year; **revenue = all Sale totals + delivered Order totals**; payload `{totalSales, totalRevenue, paidSales, pendingSales, averageOrderValue, topProducts(5)}`. List date filter has no end-of-day.

## Purchases (`user-purchases.controller.ts`)
- Number `PO-YYYYMMDD-NNNN`. Statuses `pending, partial, received, cancelled`; PUT allows only pending→cancelled, partial→cancelled; partial/received only via receive.
- Create: supplierId (own, optional), items {productId, variantId, quantity>0, unitCost≥0|null}, tax, shippingCost, paymentStatus (pending), paymentMethod, amountPaid, purchaseDate ≤ +1 day, expectedDate, notes; status always pending; variant needs variantId; **inactive products allowed**. Total = Σ(unitCost×qty) + tax + shipping. Caisse: paid>0 → auto expense row category purchase.
- Receive: items[{itemId, receivedQty}] (amount received now); over-receive `PURCHASE_OVER_RECEIVE`; variant restock (fallback parent); `in` movement reference purchaseId; status received (+receivedDate) when all lines complete else partial. **costPrice never updated. trackStock not checked.**

Cancel: reverses received stock with negative adjustments, receivedQty→0, amountPaid→0, deletes auto caisse rows, returns note to record refund manually. Paid change → recompute auto rows.
- Delete: only pending, amountPaid 0, nothing received; deletes auto rows + purchase.
- Stats: default month, cancelled excluded: `{totalPurchases, totalSpent=ΣamountPaid, committedTotal=Σtotal, pendingPurchases, receivedPurchases, topSuppliers(5)}`. List end date no end-of-day.

## Orders (`user-orders.controller.ts`)
- Number `ORD-YYYYMMDD-NNNN` (UTC), shared sequence manual/AI, in-transaction, 3 retries.
- Enums: status `pending, confirmed, preparing, shipped, delivered, cancelled, returned`; paymentMethod `cash, card, transfer, ccp`; paymentStatus `pending, partial, paid`; deliveryStatus `not_sent, sent, in_transit, delivered`; confirmationStatus `not_called, no_answer, confirmed, rejected`; call results `picked_up, no_answer, busy, rejected, voicemail`; source `manual, ai`.
- Create: clientName ≤191 + items required; optional clientId (own), clientPhone ≤50 (**not validated**), notes, discount, tax, amountPaid, paymentMethod (cash), status (default pending, **any status allowed at creation**), source (manual), isStopdesk, orderDate ≤ +1 day, deliveryFee ≥0. **clientAddress, wilayaId, communeName not validated** (wilayaId no 1-58 check). Items same checks as sales (`ORDER_VARIANT_REQUIRED/NOT_FOUND`, `ORDER_INSUFFICIENT_STOCK`). Creating with status cancelled still deducts stock. Fee: explicit deliveryFee wins, else computeDeliveryFee if wilayaId, else 0. total = subtotal − discount + tax + deliveryFee. amountPaid clamped; paid/partial/pending; zero-total order → paid with 0 (and a 0-amount caisse row). Caisse auto income (category order, dated orderDate) when paid or actualPaid>0. Client counters incremented.
- Update: transitions pending→confirmed|preparing|shipped|delivered|cancelled; confirmed→preparing|shipped|delivered|cancelled; preparing→shipped|delivered|cancelled; shipped→delivered|returned; delivered→returned; cancelled/returned terminal (`ORDER_TERMINAL`), else `ORDER_INVALID_TRANSITION`. Terminal orders lock payment/delivery (`ORDER_TERMINAL_PAYMENT_LOCKED`). **COD: → delivered while unpaid sets amountPaid=total + caisse row "(COD - delivered)".** paymentStatus alone (no amountPaid) stored as-is (can disagree). deliveryStatus free, not linked to status. clientPhone/clientAddress editable unvalidated. → cancelled/returned runs `rollbackOrderSideEffects` then amountPaid 0 / pending. Paid change → recompute auto rows.
- `rollbackOrderSideEffects` (:57-116): restores stock (variant fallback product) + `return` movements; recalcs parents; deletes **all auto** caisse rows for order; decrements client totalOrders/totalSpent (lastOrderDate not reset; can go negative). Runs for returned too (delivered COD returned → income deleted, stock re-shelved).
- Delete: delivered blocked (`ORDER_DELETE_DELIVERED`); non-terminal rolled back first (inline duplicate); **all** caisse rows with sourceId incl. manual deleted.
- addOrderCall: picked_up→confirmed (status confirmed if pending); rejected→rejected (auto-cancel only if status pending|confirmed|preparing and deliveryStatus not_sent); no_answer/busy/voicemail→no_answer; callAttempts++; picked_up on cancelled/returned logs + warning.
- **No bulk operations, no export** (routes: stats, list, get, create, update, delete, calls).
- Stats: periods today/week/month(default)/year; totalOrders/totalRevenue exclude cancelled/returned but **include pending**; paidOrders/paidAmount; per-status counts; delivery counts notSent/sent/inTransit/deliveredDelivery; averageOrderValue; topProducts(5). List: no end-of-day; search number, client fields, notes, item productName.

## Cross-sell (`user-cross-sell.controller.ts`, `recommendation.service.ts`)
- Generation **rule-based, not AI**: co-purchase (non-cancelled orders incl. returned + sales; score = pairCount/ordersContainingA ≥0.1, cross_sell "Bought together N time(s)"), category up-sell (up to 3 pricier in category, score = src/target ≥0.1), description Jaccard ≥0.15 cross-category (>1.2× price → up_sell else cross_sell both ways; O(n²)). Merged by productId:recommendedId:type, upserted; **stale pairs never deleted**.
- Fields type, score, reason, impressions, conversions, revenue, isActive. API: list (search in-memory, type, isActive) bare array; product top 10; PUT isActive only; DELETE. Stats `{total, active, totalImpressions, totalConversions, conversionRate, totalRevenue}`.
- Impressions: +1 per matched `[RECOMMEND:src:rec]` tag in AI reply (webhook.controller.ts:685-711). Conversions: every ordered pair in an AI order with an active rule (ai.service.ts:936-953); not linked to impressions; manual orders/sales never counted; cancellations not reversed.
